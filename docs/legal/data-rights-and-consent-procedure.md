# Data Rights, Consent, and Grievance Procedure

Status: **Draft operational procedure**
Version: `draft-0.1`

## Intake Channels

1. School-record requests start with the relevant institution.
2. JinaCampus privacy/grievance requests use the approved public contact once named.
3. Support staff must never request passwords, reset tokens, session cookies, full payment details, or unnecessary identity documents.
4. Every request receives a secret-free evidence reference and acknowledgement through a verified channel.

## Verification

- Verify the requester with the minimum information needed.
- For a child, verify parent/lawful-guardian authority or other lawful representation.
- For staff records, verify the staff relationship and current contact channel.
- For an institution request, verify the authorised administrator and tenant scope.
- Route disputes about school-record accuracy to the Institution while preserving JinaCampus grievance escalation.

## Request Workflow

| Request | Required action |
|---|---|
| Access/summary | Identify systems and categories; obtain institution approval; deliver through a protected channel |
| Correction/completion | Validate authoritative evidence; use audited application workflow; preserve historical integrity |
| Export | Define scope/format; apply tenant and branch filters; securely deliver; expire temporary files |
| Erasure | Run retention/legal-hold assessment; obtain authority; delete/anonymise through controlled workflow |
| Consent withdrawal | Identify affected purpose/channel; explain service consequences; disable future processing where permitted; retain withdrawal evidence |
| Grievance | Assign owner; investigate; record decision and escalation route; do not expose another person's data |
| Nomination | Verify applicability, requester and nominee authority under rules effective at the request date |

## Consent Standard

Consent evidence must be purpose-specific and record:

- data subject and, where applicable, verified parent/lawful guardian;
- institution, purpose, data categories, channel and recipient;
- notice/document version and language;
- affirmative action, source, timestamp and verification method;
- withdrawal method, timestamp and effect;
- any lawful non-consent basis approved by counsel.

The presence of a phone number, email address, student enrollment, login, or uploaded document is not by itself consent for optional communication or unrelated processing. Withdrawal must be as easy as consent unless a documented legal constraint applies.

## Product Gap and Release Gate

Communication preferences currently retain limited consent date/source evidence. JinaCampus does not yet have a universal, versioned legal-acceptance and data-rights ledger. Before public self-service onboarding, Product, Legal, and Engineering must approve an additive, tenant-scoped model and authenticated workflow with audit logs, rate limits, safe notifications, exports, correction, deletion review, and status tracking.

Until then, institutions must use an approved external case register and attach only secret-free evidence references to JinaCampus support/audit records. This interim process requires counsel approval.
